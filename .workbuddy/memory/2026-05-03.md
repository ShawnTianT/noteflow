### 线上主流程 bug 修复（13:09）

- **根因**：
  1. `db.js` 的 `getNotes()` 返回纯数组，app.js 按 `{ data, total }` 取值 → result.data 为 undefined
  2. `getNoteCount()` 标签 SQL 匹配用6个OR条件，标签在末尾时匹配不到
  3. db.js 参数名 `page`（从0开始）vs app.js 传 `pageCurrent`（从1开始）
- **修复**：
  1. `getNotes()` 返回格式改为 `{ data, total, hasMore }`（已在之前完成）
  2. `getNoteCount()` 标签匹配改用 `',' || tags || ',' LIKE '%,' || ? || ',%'` 包裹方式
  3. `getNotes()` 兼容 `pageCurrent` 参数，自动转换为从0开始的 `page`

### 第二轮代码审查修复（14:53）— v1.3.1
- **问题2（必修）**：离线标签计数不更新
  - db-supabase.js 的 addNote/updateNote/deleteNote 没有调用 updateTagCount
  - 修复：三个函数都加上标签计数更新（旧标签-1、新标签+1）
- **问题3（必修）**：Date.now() 生成 ID 可冲突
  - addNote 用裸 Date.now()，快速连发可能 ID 重复导致 IndexedDB 覆盖丢数据
  - 修复：改为 `Math.floor(Date.now() + Math.random() * 10000)`
  - addNotesBatch 同步修改
- **问题1（小修）**：clearSearch debounce 定时器残留
  - SearchModule.clearSearch() 只清 input 不清定时器，可能在标签筛选后触发残留搜索
  - 修复：clearSearch 里加 `clearTimeout(debounceTimer)`
- **问题4（小修）**：导入时间戳字段名不一致
  - db-supabase.js addNotesBatch 只读 note.created_at，没有 note.createdAt 兜底
  - 修复：改为 `note.created_at || note.createdAt || now`
- **问题8（小修）**：搜索不分词
  - db-supabase.js 搜索只做 includes(keyword)，和 db.js 的 split(/\s+/) AND 搜索不一致
  - 修复：改为 `keywords.every(kw => ...)` 多关键词 AND 逻辑
